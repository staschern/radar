## 1. Проблема

Исходящий трафик сессии проходит через прокси, применяющий сетевую политику
окружения. Уровень доступа по умолчанию — **Trusted**: разрешены реестры пакетов,
GitHub и облачные SDK, всё остальное отклоняется на уровне шлюза.

Так выглядела диагностика до разблокировки:
```
$ python3 scripts/fetch_market_data.py --check
  ❌ iss.moex.com (котировки) — заблокировано политикой окружения
  ❌ www.cbr.ru (курсы валют) — заблокировано политикой окружения
```
После настройки окружения (см. §2) — обе позиции зелёные. Изменение применилось
сразу, без перезапуска сессии, хотя диалог предупреждает про новые сессии.
В логе прокси: `connect_rejected · gateway answered 403 to CONNECT (policy denial)`.

**Это не ошибка и не сбой.** Обходить такой отказ нельзя, и агент не может изменить
политику из сессии — уровень доступа задаётся владельцем окружения в интерфейсе.

**Что при этом работает:** веб-поиск не зависит от этой политики, поэтому радар
собирается полностью — индексы, курсы, ставки, кривая ОФЗ, инфляция, сырьё, новости.
Недоступны именно **котировки отдельных инструментов** и первичные данные с cbr.ru.

## 2. Как разрешить домены

1. Открыть селектор окружения (значок облака) на claude.ai/code, в мобильном или
   Desktop-приложении и открыть окружение на редактирование. Отдельной страницы для
   личных окружений в настройках аккаунта нет — только этот селектор.
2. Поле **Network access** → выбрать **Custom**.
3. В поле **Allowed domains** указать по одному домену на строку:
   ```text
   iss.moex.com
   *.moex.com
   *.cbr.ru
   rosstat.gov.ru
   ```
4. **Обязательно отметить «Also include default list of common package managers».**
   Без этой галочки список заменяет Trusted-домены целиком, и сессия потеряет
   доступ к реестрам пакетов и GitHub — то есть сломается то, что сейчас работает.

Альтернатива — уровень **Full** (любой домен): проще, не требует поддержки списка,
но шире по доступу. Для этого проекта достаточно **Custom**.

Изменение применяется к новым сессиям в этом окружении.

### Проверка после изменения
```bash
python3 scripts/fetch_market_data.py --check
```
Ожидаемый вывод — две зелёные галочки. Затем:
```bash
python3 scripts/fetch_market_data.py --date 2026-08-21
```

## 4. MOEX ISS API — что нужно знать

Открытый API Московской биржи. **Ключ и регистрация не нужны.** Базовый адрес —
`https://iss.moex.com/iss`. Ответ в JSON при добавлении `.json` к пути.

### Режимы торгов, покрывающие допустимую вселенную активов

| Что | Engine / Market / Board |
|---|---|
| Акции | `stock / shares / TQBR` |
| ОФЗ | `stock / bonds / TQOB` |
| БПИФ (золото, денежный рынок) | `stock / shares / TQTF` |
| Индексы (IMOEX, RGBI) | `stock / index / SNDX` |

### Основные запросы

**Итоги торгов за дату:**
```
/iss/history/engines/stock/markets/shares/boards/TQBR/securities.json?date=2026-08-17
```
Ключевые поля: `SECID`, `CLOSE`, `OPEN`, `VOLUME`, `VALTODAY`, `NUMTRADES`.
Для облигаций цена закрытия — в `LEGALCLOSEPRICE`, а не в `CLOSE`.

**Размеры лотов** (в истории торгов их нет — только в справочнике):
```
/iss/engines/stock/markets/shares/boards/TQBR/securities.json?iss.only=securities&securities.columns=SECID,LOTSIZE
```

**Официальные курсы ЦБ** (не через ISS):
```
https://www.cbr.ru/scripts/XML_daily.asp?date_req=18/08/2026
```
Возвращает XML; курс делится на `Nominal`. Курс на дату публикуется **накануне**.

### Особенности, о которые легко споткнуться
- Пагинация: ответ отдаёт до 100 строк, следующая страница — параметром `start`.
- `iss.meta=off` и `iss.only=<блок>` заметно сокращают ответ.
- В выходные и праздники история пуста — это не ошибка, а отсутствие торгов.
- Данные за текущий день появляются после закрытия сессии; на 09:00 мск в истории
  лежит предыдущий торговый день.
- Одна бумага торгуется в нескольких режимах — брать только целевой board,
  иначе получите дубли с разными ценами.

## 5. Скрипт

`scripts/fetch_market_data.py` — загрузчик, готовый к работе сразу после
разблокировки. Умеет:
- `--check` — диагностика доступа к источникам с подсказкой по настройке;
- `--date YYYY-MM-DD` — выгрузка по всем четырём режимам + курсы ЦБ;
- `--tickers SBER,LKOH` — фильтр по инструментам.

Результат — `data/quotes/YYYY-MM-DD.json`: цены, объёмы, размеры лотов, курсы.
Ошибки не глотаются: недоступные источники попадают в поле `errors`, а частичный
результат всё равно сохраняется.

## 6. Практика первой выгрузки (18.08.2026)

Что выяснилось при реальном использовании — учтено в скрипте:

- **БПИФ торгуются в TQBR, а не в отдельном режиме.** Борд `TQTF` вернул ноль
  инструментов; у LQDT, TGLD, GOLD, AKMM `is_primary` борд — `TQBR`. Проверять
  режим бумаги: `/iss/securities/<TICKER>.json?iss.only=boards`.
- **Ограничение колонок обязательно.** Полный ответ по TQBR (505 бумаг) рвал
  соединение с `Connection reset by peer`. С `history.columns=SECID,SHORTNAME,CLOSE,OPEN,VOLUME`
  проходит стабильно.
- **Справочник лотов целиком выгружать нельзя** — сотни поштучных страниц,
  минуты и обрывы. Запрашивать лот только для нужных бумаг, поштучно.
- **ISS периодически рвёт соединение** даже на мелких запросах: нужен retry
  с нарастающей паузой (в скрипте 3 попытки).
- **ЦБ отдаёт XML в windows-1251**, а не в UTF-8.
- **Цена облигации в истории торгов чистая**, без НКД. НКД — отдельным запросом,
  поле `ACCRUEDINT`; без него стоимость позиции занижена (по 26238 это 14,98 ₽
  на облигацию, около 3% суммы позиции).
