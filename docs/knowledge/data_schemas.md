# Схемы данных

Единый справочник по формату файлов в `data/`. Все файлы — **append-only**.

---

## 1. `data/radar_history.jsonl`
Одна строка JSON = один торговый день. Без переносов внутри строки.

| Поле | Тип | Описание |
|---|---|---|
| `date` | string | `YYYY-MM-DD`, дата отчёта |
| `imoex` | number\|null | Значение индекса МосБиржи (закрытие пред. дня) |
| `imoex_chg_d` | number\|null | Изменение за день, % |
| `imoex_chg_w` | number\|null | Изменение за неделю, % (к закрытию пятницы) |
| `usdrub` | number\|null | Курс ЦБ РФ |
| `cnyrub` | number\|null | Курс ЦБ РФ |
| `key_rate` | number\|null | Ключевая ставка ЦБ, % |
| `ruonia` | number\|null | RUONIA, % |
| `rgbi` | number\|null | Индекс гособлигаций |
| `ofz1y` | number\|null | Доходность ОФЗ 1 год, % |
| `ofz10y` | number\|null | Доходность ОФЗ 10 лет, % |
| `brent` | number\|null | $/барр. |
| `gold` | number\|null | $/унц. |
| `cpi_w` | number\|null | Недельная инфляция, % |
| `cpi_y` | number\|null | Годовая инфляция, % |
| `trigger` | string | Главный триггер дня, одно предложение |
| `risk_score` | integer | Оценка ключевого риска дня, 0–100 (**аналитическая оценка**) |
| `flag_portfolio_review` | boolean | Нужен ли внеплановый пересмотр портфеля |
| `movers` | array | Топ-движения дня: `[{"t":"AFKS","chg":7.2}, …]`, до 5 элементов |
| `report` | string | Относительный путь к HTML-отчёту |
| `notes` | string? | Примечания о качестве данных: что внутридневное, что усреднено, чего нет |
| `corrects` | string? | Только для строк-исправлений: дата исправляемой записи |

**Правила**
- Нет данных → `null`. Никогда не подставлять последнее известное значение молча.
- `risk_score` и уровни — эвристика, не факт; в отчёте помечаются как оценка.
- Строки не редактируются. Исправление = новая строка с `corrects`.
- Порядок строк — хронологический (дописывание в конец).

## 2. `data/portfolio_history.jsonl`
Одна строка = один пересмотр портфеля.

| Поле | Тип | Описание |
|---|---|---|
| `date` | string | `YYYY-MM-DD` |
| `total_value` | number | Стоимость портфеля, ₽, **с рыночной переоценкой**, после зачисления взноса |
| `contribution` | number | Взнос этой даты, ₽ (0, если пересмотр не пятничный) |
| `contributions_total` | number | Сумма всех взносов с дня 0 |
| `net_invested` | number | `1 000 000 + contributions_total` — вложено всего |
| `pnl_rub` | number | `total_value − net_invested` — фактическая прибыль, ₽ |
| `pnl_pct` | number | `pnl_rub / net_invested × 100`, % |
| `twr_pct` | number | Time-Weighted Return с дня 0, % — [methodology §9](methodology.md) |
| `value_before_contribution` | number | Стоимость **до** зачисления взноса — нужна для расчёта TWR |
| `drawdown_pct` | number | Текущая просадка от пика по кривой TWR, % (≤0) |
| `trigger` | string | `start` \| `weekly` \| `adhoc` \| `profile_change` |
| `reason` | string | Краткая причина пересмотра / основной драйвер решения |
| `contribution_to` | string | Куда направлен взнос (класс/тикер или «денежный рынок») |
| `allocations` | array | `[{"class":"акции","ticker":"SBER","pct":15,"value":151575,"lots":5}, …]` |
| `prices_asof` | string | Дата цен, по которым посчитаны позиции (может отличаться от `date`) |
| `fee_rub` | number | Комиссия сделок этого пересмотра, ₽ |
| `cash_rub` | number | Неразмещённый денежный остаток, ₽ |
| `notes` | string? | Примечания о качестве данных и принятых допущениях |
| `corrects` | string? | Только для строк-исправлений: дата исправляемой записи |
| `report` | string | Относительный путь к HTML-отчёту |

**Правила**
- Сумма `pct` по всем позициям = 100 (допуск округления ±0.5).
- Позиция хранит `lots` (целых лотов) и `units` (штук); дробные лоты не используются.
- Класс — одно из: `акции`, `облигации`, `золото`, `кэш`.
- Первая строка всегда `"trigger":"start"`, фиксирует день 0, `contribution: 0`,
  `net_invested: 1000000`, `twr_pct: 0`.
- `twr_pct` **нельзя** заменять на `pnl_pct` при сравнении с IMOEX — см. methodology §9.
- Позиции хранят целое число лотов; дробные лоты не используются.

## 2а. `data/control_portfolio_history.jsonl`
Контрольный портфель (ТЗ Портфель §11). **Та же схема, что и §2**, плюс:

| Поле | Тип | Описание |
|---|---|---|
| `deviation_pp` | object | Отклонение долей классов от основного портфеля, п.п.: `{"акции":-4.2,"кэш":+4.2}` |
| `twr_gap_pp` | number | Разница TWR с основным портфелем, п.п. (отрицательное = отстаёт) |
| `unbuyable` | array | Позиции, недоступные из-за размера лота: `[{"ticker":"LKOH","lot_cost":4221.5,"weeks_to_afford":3}]` |
| `mm_buffer_rub` | number | Накопленный буфер в фонде денежного рынка, ₽ |

Первая строка — `"trigger":"start"` с `total_value: 0`, датой 2026-08-21.

## 2б. Позиции с правилом фиксации прибыли
Элемент массива `allocations` расширяется для акций, к которым применяется
правило §10 ТЗ Портфель:

| Поле | Тип | Описание |
|---|---|---|
| `avg_price` | number | Средняя цена покупки с учётом всех докупок |
| `position_return_pct` | number | `текущая цена / avg_price − 1`, % |
| `core_lots` | integer | Лоты ядра (50%), правилом фиксации не трогаются |
| `tactical_lots` | integer | Лоты тактической части, доступные для фиксации |
| `steps_fired` | array | Сработавшие ступени фиксации: `[50, 62]` |
| `peak_since_fix` | number | Максимум цены после последней фиксации — база для откупа |
| `parked_rub` | number | Сумма, выведенная в консервативные инструменты по этой бумаге |

**Правила**
- Средняя цена при частичной продаже **не пересчитывается** — уменьшается только
  количество лотов.
- Ступень фиксации срабатывает однократно за цикл; цикл завершается возвратом
  позиции к 100% целевого объёма.
- `core_lots` уменьшается только при обычной ребалансировке по фундаментальным
  основаниям, а не по правилу фиксации.

## 3. `data/watchlist_config.json`
Фиксированный слой watchlist. **Стартует пустым.** Правится только по указанию
пользователя.

```json
{
  "version": 1,
  "updated": "2026-08-18",
  "tickers": [],
  "notes": "Список пуст. Наполняется по указанию пользователя."
}
```

При добавлении тикера в `history` дописывается запись — когда и почему добавили,
чтобы через полгода было понятно, зачем бумага в списке:

```json
{"date":"2026-09-01","action":"add","ticker":"SBER","reason":"ядро портфеля"}
```

## 4. `data/daily/YYYY-MM-DD.md`
Человекочитаемая сводка дня. Шаблон — [`docs/knowledge/daily_summary_template.md`](daily_summary_template.md).
Жёсткий лимит: ~40 строк. Если не влезает — сокращать, а не расширять шаблон.
