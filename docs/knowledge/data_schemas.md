# Схемы данных

Единый справочник по формату файлов в `data/`. Все файлы — **append-only**.

---

## 1. `data/radar_history.jsonl`
Одна строка JSON = один торговый день. Без переносов внутри строки.

| Поле | Тип | Описание |
|---|---|---|
| `date` | string | `YYYY-MM-DD`, дата отчёта |
| `imoex` | number\|null | Значение индекса МосБиржи (закрытие пред. дня) |
| `imoex_chg_d` | number\|null | Изменение за день, % |
| `imoex_chg_w` | number\|null | Изменение за неделю, % (к закрытию пятницы) |
| `usdrub` | number\|null | Курс ЦБ РФ |
| `cnyrub` | number\|null | Курс ЦБ РФ |
| `key_rate` | number\|null | Ключевая ставка ЦБ, % |
| `ruonia` | number\|null | RUONIA, % |
| `rgbi` | number\|null | Индекс гособлигаций |
| `ofz1y` | number\|null | Доходность ОФЗ 1 год, % |
| `ofz10y` | number\|null | Доходность ОФЗ 10 лет, % |
| `brent` | number\|null | $/барр. |
| `gold` | number\|null | $/унц. |
| `cpi_w` | number\|null | Недельная инфляция, % |
| `cpi_y` | number\|null | Годовая инфляция, % |
| `trigger` | string | Главный триггер дня, одно предложение |
| `risk_score` | integer | Оценка ключевого риска дня, 0–100 (**аналитическая оценка**) |
| `flag_portfolio_review` | boolean | Нужен ли внеплановый пересмотр портфеля |
| `movers` | array | Топ-движения дня: `[{"t":"AFKS","chg":7.2}, …]`, до 5 элементов |
| `report` | string | Относительный путь к HTML-отчёту |
| `notes` | string? | Примечания о качестве данных: что внутридневное, что усреднено, чего нет |
| `corrects` | string? | Только для строк-исправлений: дата исправляемой записи |

**Правила**
- Нет данных → `null`. Никогда не подставлять последнее известное значение молча.
- `risk_score` и уровни — эвристика, не факт; в отчёте помечаются как оценка.
- Строки не редактируются. Исправление = новая строка с `corrects`.
- Порядок строк — хронологический (дописывание в конец).

### 1а. Дополнительные поля *(добавлено 2026-09-09, глобальный макро-блок, ТЗ Радар §4б)*
Только показатели с действительно **дневной** частотой обновления — остальные

либо повторять старое значение молча (запрещено §1 выше), либо создавать
ложное впечатление ежедневного обновления.

| Поле | Тип | Описание |
|---|---|---|
| `ust2y` | number\|null | Доходность казначейских облигаций США 2 года, % |
| `ust10y` | number\|null | Доходность казначейских облигаций США 10 лет, % |
| `ust10y_real` | number\|null | Реальная доходность 10Y (breakeven, FRED `T10YIE`), % |

| `gold_usd_oz` | number\|null | Золото, $/унц. Отдельное от существующего `gold` (₽/грамм, GLDRUB_TOM) — см. примечание о путанице единиц в global_macro_reserve_currency.md §5 |
| `btc_usd` | number\|null | Биткоин, $ |

Методология и источники — [global_macro_reserve_currency.md §2.3, §3, §5](global_macro_reserve_currency.md).

## 2. `data/portfolio_history.jsonl`
Одна строка = один пересмотр портфеля.

| Поле | Тип | Описание |
|---|---|---|
| `date` | string | `YYYY-MM-DD` |
| `total_value` | number | Стоимость портфеля, ₽, **с рыночной переоценкой**, после зачисления взноса |
| `contribution` | number | Взнос этой даты, ₽ (0, если пересмотр не пятничный) |
| `contributions_total` | number | Сумма всех взносов с дня 0 |
| `net_invested` | number | `1 000 000 + contributions_total` — вложено всего |
| `pnl_rub` | number | `total_value − net_invested` — фактическая прибыль, ₽ |
| `pnl_pct` | number | `pnl_rub / net_invested × 100`, % |
| `twr_pct` | number | Time-Weighted Return с дня 0, % — [methodology §9](methodology.md) |
| `value_before_contribution` | number | Стоимость **до** зачисления взноса — нужна для расчёта TWR |
| `drawdown_pct` | number | Текущая просадка от пика по кривой TWR, % (≤0) |
| `trigger` | string | `start` \| `weekly` \| `adhoc` \| `profile_change` |
| `reason` | string | Краткая причина пересмотра / основной драйвер решения |
| `contribution_to` | string | Куда направлен взнос (класс/тикер или «денежный рынок») |
| `allocations` | array | `[{"class":"акции","ticker":"SBER","pct":15,"value":151575,"lots":5}, …]` |
| `prices_asof` | string | Дата цен, по которым посчитаны позиции (может отличаться от `date`) |
| `fee_rub` | number | Комиссия сделок этого пересмотра, ₽ |
| `cash_rub` | number | Неразмещённый денежный остаток, ₽ |
| `stock_reserve_rub` | number | *(с 11.09.2026, ТЗ §10в.2а)* Сумма `parked_rub` (§2б) по всем позициям с активным циклом фиксации — деньги физически в облигациях/кэше, но экономически часть доли акций |
| `effective_stock_pct` | number | *(с 11.09.2026)* `(Σ value акций + stock_reserve_rub) / total_value × 100` — сверяется с целевой долей акций по §10в, а не факт. доля |
| `effective_bond_pct` | number | *(с 11.09.2026)* `(Σ value облигаций+кэша − stock_reserve_rub) / total_value × 100` — зеркально `effective_stock_pct` |
| `notes` | string? | Примечания о качестве данных и принятых допущениях |
| `corrects` | string? | Только для строк-исправлений: дата исправляемой записи |
| `report` | string | Относительный путь к HTML-отчёту |

**Правила**
- Сумма `pct` по всем позициям = 100 (допуск округления ±0.5).
- Позиция хранит `lots` (целых лотов) и `units` (штук); дробные лоты не используются.
- Класс — одно из: `акции`, `облигации`, `золото`, `кэш`.
- Первая строка всегда `"trigger":"start"`, фиксирует день 0, `contribution: 0`,
  `net_invested: 1000000`, `twr_pct: 0`.
- `twr_pct` **нельзя** заменять на `pnl_pct` при сравнении с IMOEX — см. methodology §9.
- Позиции хранят целое число лотов; дробные лоты не используются.
- `stock_reserve_rub` = 0, если ни одна позиция не находится в активном цикле
  фиксации — тогда `effective_stock_pct`/`effective_bond_pct` совпадают с
  фактическими долями по классам. Поле пишется всегда (даже при 0), а не
  пропускается, чтобы отличать «резервов нет» от «не посчитано».

## 1а. Размер лота по инструментам (справочник)

**Критично для расчёта покупок/продаж в обоих портфелях.** Лот — минимальная
покупаемая порция бумаги на MOEX; для многих ликвидных акций он **не равен
одной штуке**. Перед любой ребалансировкой лот каждого инструмента нужно
проверять через MOEX ISS (`securities.columns=SECID,LOTSIZE`), а не
предполагать по умолчанию — источник ошибки 04.09.2026 (см.
`portfolio_decisions_log.md`, запись от этой даты) был именно в этом:
SNGSP/GMKN/MOEX куплены поштучно вместо целых лотов по 10 акций.

Проверено через MOEX ISS 04.09.2026 (актуальность — сверять периодически,
лот может меняться решением биржи):

| Тикер | Лот (шт.) | Где используется |
|---|---|---|
| SBER, LKOH, PLZL, ROSN, T, YDEX, TATN, BELU, OZON | 1 | модельный/контрольный портфель, watchlist |
| GOLD (БПИФ ВИМ Золото), LQDT (БПИФ ВИМ Ликвидность) | 1 | модельный/контрольный портфель |
| ОФЗ 26238, ОФЗ 26243, ВЭБ2Р-50, Газпн3P13R, РостелP16R (и облигации вообще, если не указано иное) | 1 | модельный портфель |
| **SNGSP, GMKN, MOEX** | **10** | модельный/контрольный портфель — держать количество кратным 10 |
| **BSPB, LSNGP, RENI** | **10** | watchlist — учитывать при возможном включении в портфель |
| **IRAO** | **100** | watchlist |
| **HYDR** | **1000** | watchlist |

**Правило применения (ТЗ §11.2 и §12, оба портфеля).** Везде, где алгоритм
говорит «купить/продать целых лотов, не превышая/не опускаясь ниже целевой
суммы», лот — это `LOTSIZE × цена одной штуки`, а не цена одной штуки. Для
инструментов с лотом >1 целевая сумма меньше стоимости одного лота — это
**структурный барьер** (см. §11.2), даже если целевая сумма выше цены одной
штуки. Пример: у GMKN лот = 10 шт., при цене 130,36 ₽/шт. лот стоит 1 303,60 ₽ —
если целевая сумма в контрольном портфеле, скажем, 450 ₽, это структурный
барьер, а не «купить 3 акции».

## 2а. `data/control_portfolio_history.jsonl`
Контрольный портфель (ТЗ Портфель §11). **Та же схема, что и §2**, плюс:

> Контрольный портфель повторяет решения основного (§11.2), включая фиксации
> и доборы по правилу §10 — значит поля `stock_reserve_rub`,
> `effective_stock_pct`, `effective_bond_pct` (см. §2) считаются и здесь, по
> той же формуле, от собственных позиций и собственного `total_value`
> контрольного портфеля, а не копируются из основного.

| Поле | Тип | Описание |
|---|---|---|
| `deviation_pp` | object | Отклонение долей классов от основного портфеля, п.п.: `{"акции":-4.2,"кэш":+4.2}` |
| `deviation_pp_instrument` | object | *(с 28.08.2026, ТЗ §11.2)* То же по каждому инструменту, не только по классам: `{"PLZL":+39.2,"LKOH":-4.6}` |
| `twr_gap_pp` | number | Разница TWR с основным портфелем, п.п. (отрицательное = отстаёт) |
| `unbuyable` | array | Позиции, недоступные из-за размера лота: `[{"ticker":"LKOH","lot_cost":4221.5,"barrier":"structural","weeks_to_afford":null}]`. С 28.08.2026 у каждого элемента поле `barrier`: `"temporary"` — целевая сумма достижима, копится взносами (`weeks_to_afford` — число); `"structural"` — целевая сумма меньше цены 1 лота, `weeks_to_afford` не имеет смысла (`null`), снимается только ростом общей стоимости портфеля — см. `TZ_Model_Portfolio.md` §11.2 |
| `mm_buffer_rub` | number | Накопленный буфер в фонде денежного рынка, ₽ |

Первая строка — `"trigger":"start"` с `total_value: 0`, датой 2026-08-21.

## 2б. Позиции с правилом фиксации прибыли
Элемент массива `allocations` расширяется для акций, к которым применяется
правило §10 ТЗ Портфель:

| Поле | Тип | Описание |
|---|---|---|
| `avg_price` | number | Средняя цена покупки с учётом всех докупок |
| `position_return_pct` | number | `текущая цена / avg_price − 1`, % |
| `core_lots` | integer | Лоты ядра (50%), правилом фиксации не трогаются |
| `tactical_lots` | integer | Лоты тактической части, доступные для фиксации |
| `steps_fired` | array | Сработавшие ступени фиксации: `[50, 62]` |
| `peak_since_fix` | number | Максимум цены после последней фиксации — база для откупа |
| `parked_rub` | number | Сумма, выведенная в консервативные инструменты по этой бумаге |
| `income_rub` | number | Полученные по позиции дивиденды и купоны за всё время владения |
| `position_return_with_income_pct` | number | Доходность позиции с учётом дивидендов и купонов, % |
| `to_next_fix_pct` | number\|null | Сколько % роста до ближайшей несработавшей ступени фиксации |
| `to_next_buy_pct` | number\|null | Сколько % падения от пика до ближайшей ступени откупа; `null`, если фиксаций не было |
| `ytm_pct` | number? | Только облигации: доходность к погашению |
| `duration_years` | number? | Только облигации: дюрация в годах |

**Правила**
- Средняя цена при частичной продаже **не пересчитывается** — уменьшается только
  количество лотов.
- Ступень фиксации срабатывает однократно за цикл; цикл завершается возвратом
  позиции к 100% целевого объёма.
- `core_lots` уменьшается только при обычной ребалансировке по фундаментальным
  основаниям, а не по правилу фиксации.

## 3. `data/watchlist_config.json`
Фиксированный слой watchlist. Правится по указанию пользователя и автоматически
при поступлении идеи аналитика с уровнями (ТЗ Радар §9.1).

```json
{
  "version": 2,
  "updated": "2026-08-18",
  "tickers": ["ROSN"],
  "notes": "…",
  "levels": {
    "ROSN": {
      "entry_zone": [260.0, 270.0],
      "resistance": [350.0],
      "support": [],
      "analyst": "Александр Полярный",
      "received": "2026-08-18",
      "published": null,
      "note": "Уведомление на покупку в зоне 260–270 ₽…",
      "in_portfolio": true,
      "outcome": null
    }
  },
  "history": [
    {"date": "2026-08-18", "action": "add", "ticker": "ROSN",
     "reason": "…", "analyst": "Александр Полярный"}
  ]
}
```

| Поле в `levels[TICKER]` | Тип | Описание |
|---|---|---|
| `entry_zone` | array | Зона добора: `[от, до]` или несколько уровней |
| `resistance` / `support` | array | Уровни сопротивления и поддержки из идеи |
| `analyst` | string\|null | Имя автора идеи. `null`, если источник неизвестен |
| `published` | string\|null | Дата публикации идеи, `YYYY-MM-DD`. `null` — неизвестна |
| `received` | string | Дата, когда заказчик прислал идею — **обязательно** |
| `note` | string | Суть идеи в одном-двух предложениях |
| `in_portfolio` | boolean | Есть ли бумага в модельном портфеле |
| `outcome` | string\|null | Исход: `hit_entry` \| `hit_target` \| `invalidated` \| `expired` \| `null` (открыта) |

**Правила**
- Новая идея по той же бумаге **не затирает** прежнюю: старая запись получает
  `outcome`, новая добавляется. История предсказаний сохраняется целиком.
- Если дата публикации неизвестна, в отчёте указывается дата получения с
  пометкой «получено», а не выдаётся за дату публикации.
- Исходы идей сводятся в [`analyst_scorecard.md`](analyst_scorecard.md).

## 3а. `data/watchlist_inflation_hedge.json`
*(добавлено 2026-09-09, ТЗ Радар §9.3)* Третий, тематический слой watchlist —
акции, устойчивые к инфляции/девальвации рубля по критериям
[global_macro_reserve_currency.md §6](global_macro_reserve_currency.md).
**В отличие от `watchlist_config.json`, агент может сам предлагать и добавлять
кандидатов** (см. правило в том же §6) — это единственный список, где это
разрешено по умолчанию, не только по идее аналитика.

```json
{
  "version": 1,
  "updated": "2026-09-09",
  "tickers": [],
  "criteria_ref": "docs/knowledge/global_macro_reserve_currency.md#6",
  "levels": {},
  "history": []
}
```

Структура `levels[TICKER]` и `history` — как в `watchlist_config.json` (§3),
плюс обязательное поле `criteria_match` в `levels[TICKER]`:

| Поле | Тип | Описание |
|---|---|---|
| `criteria_match` | object | По каждому из 5 критериев §6 — `true`/`false` и короткое обоснование: `{"pricing_power": [true, "…"], "hard_assets": [...], "fx_revenue": [...], "fixed_rate_debt": [...], "indexed_tariffs": [...]}` |
| `added_by` | string | `"agent"` \| `"user"` — кто инициировал добавление |

**Правила**
- Стартует пустым — первое наполнение по факту следующего запуска Радара с
  живыми данными, не по памяти агента.
- Каждое добавление агентом обязательно проходит фильтр ликвидности
  (methodology §20) и получает `criteria_match` минимум по 2 из 5 критериев с
  конкретным обоснованием, не общей фразой.
- Пользователь может удалить любую бумагу в любой момент; удаление — запись в
  `history` с причиной, не тихое исчезновение из `tickers`.

## 4. `data/daily/YYYY-MM-DD.md`
Человекочитаемая сводка дня. Шаблон — [`docs/knowledge/daily_summary_template.md`](daily_summary_template.md).
Жёсткий лимит: ~40 строк. Если не влезает — сокращать, а не расширять шаблон.

## 5. `data/global_macro_history.jsonl`
*(добавлено 2026-09-09, ТЗ Радар §4б)* Госдолг США, роль доллара, накопленное
обесценивание валют портфеля. **Не дневной append-log** — это лог событий:
новая строка пишется только когда появился новый официальный релиз хотя бы по
одному полю (месячные Treasury/BLS данные, недельный баланс ФРС, квартальный
COFER/Rosstat), а не при каждом запуске Радара. Если с прошлой строки ничего
нового не опубликовано — новая строка не создаётся, отчёт ссылается на
последнюю. Методология и источники по каждому полю —
[global_macro_reserve_currency.md](global_macro_reserve_currency.md).

| Поле | Тип | Описание |
|---|---|---|
| `date` | string | `YYYY-MM-DD`, дата записи (день, когда агент зафиксировал релиз, не обязательно дата самого релиза) |
| `us_debt_interest_pct_revenue` | number\|null | Обслуживание долга США / доходы федерального бюджета, % (§2.1) |
| `us_deficit_ltm_usd_bn` | number\|null | Дефицит бюджета США, trailing-12m, $ млрд (§2.2) |
| `us_primary_deficit_ltm_usd_bn` | number\|null | Первичный дефицит (без % платежей по долгу), $ млрд (§2.2) |
| `ust_foreign_share_pct` | number\|null | Доля иностранных держателей (official+private, TIC) в держании/новых размещениях UST, % (§2.4) |
| `ust_auction_bid_to_cover` | number\|null | Bid-to-cover последнего крупного аукциона UST (10Y/30Y), если есть новый аукцион с прошлой записи (§2.4) |
| `fed_balance_sheet_usd_tn` | number\|null | Баланс ФРС, $ трлн, по последнему H.4.1 (§2.5) |
| `fed_stance` | string\|null | `"QE"` \| `"QT"` \| `"pause"` + ставка по федфондам в `notes` (§2.5) |
| `usd_reserve_share_pct` | number\|null | Доля USD в мировых резервах ЦБ, IMF COFER, % (§3) |
| `us_cpi_index` | number\|null | Кумулятивный индекс цен США, база=100 на 2026-08-18 (§4) |
| `ru_cpi_index` | number\|null | Кумулятивный индекс цен РФ, база=100 на 2026-08-18 (§4) |
| `land_proxy_note` | string\|null | Качественная заметка по земле/недвижимости — не число, честно из-за отсутствия чистого индекса (§5) |
| `event` | string | Что именно обновилось в этой строке (например: `"TIC report Jul2026"`, `"FOMC decision"`, `"BLS CPI Aug2026"`) — **обязательное поле**, чтобы понимать, почему появилась новая строка при пустых остальных |
| `source` | string | Прямая ссылка/источник на релиз, вызвавший запись |
| `notes` | string? | Примечания о качестве данных, лагах публикации, методологических нюансах |
| `corrects` | string? | Только для строк-исправлений: дата исправляемой записи |

**Правила**
- Поля, по которым в этой конкретной записи нет нового значения (не изменились
  с прошлой строки, релиза не было) — `null`, а не повтор старого числа;
  `event`/`source` объясняют, что именно вызвало создание строки.
- Строки не редактируются, исправление — новая строка с `corrects` (как в §1).
- Кумулятивные индексы (`us_cpi_index`, `ru_cpi_index`) — цепные, каждое новое
  значение = предыдущее × (1 + месячная инфляция); при пропуске месяца
  восстанавливать цепь по факту публикации, не интерполировать искусственно.
