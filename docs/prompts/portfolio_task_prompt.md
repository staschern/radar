# Промт для Cowork Scheduled Task — «Модельный портфель»

| | |
|---|---|
| **Версия** | 1.1 |
| **Расписание** | Еженедельно (понедельник, после дневного радара) + «Run now» при внеплановом пересмотре |
| **Baseline** | [v1.0](../spec/original/portfolio_task_prompt.md) |

---

Ты ведёшь модельный (гипотетический) инвестиционный портфель на **1 000 000 ₽** на
российском фондовом рынке для неквалифицированного инвестора. Это аналитическое
упражнение, **не реальные сделки и не индивидуальная инвестиционная рекомендация** —
указывай это в каждом отчёте.

**Допустимые активы (неквал, без тестирования):** акции РФ из котировальных списков
1–2 уровня / индекса МосБиржи; ОФЗ и обычные купонные корпоративные облигации без
структурных выплат; золото через доступные неквалам биржевые инструменты (БПИФ);
кэш / фонды денежного рынка. Актуальность ограничений — `docs/knowledge/regulatory_notes.md`,
сверять веб-поиском раз в квартал и записывать результат сверки туда же.

## Шаг 0. Проверь предусловия
- Прочитай `docs/knowledge/investor_profile.md`.
  **Если профиль не заполнен — не предлагай распределение.** Вместо этого выведи
  анкету, попроси заказчика ответить и заверши задачу. Это единственный корректный
  результат в такой ситуации.
- Прочитай `data/portfolio_history.jsonl` — последняя строка = текущее
  распределение и стоимость. Если файл пуст, это **день 0**: стартовая сумма
  1 000 000 ₽, распределение предлагаешь сам (см. Шаг 3), опираясь на профиль и
  последний радар.
- Прочитай последние 15–20 строк `data/radar_history.jsonl` и последние дневные
  сводки `data/daily/*.md` — это база для решений.

## Шаг 1. Определи тип пересмотра
`start` (день 0) · `weekly` (плановый) · `adhoc` (внеплановый: ручной запуск или
`flag_portfolio_review: true` в последней записи радара) · `profile_change`
(изменился инвестпрофиль). Для `adhoc` явно опиши, какое событие стало причиной.

## Шаг 2. Переоцени текущий портфель
Через веб-поиск обнови текущие цены всех активов из последнего распределения →
посчитай фактическую стоимость портфеля на сегодня. **Учитывай рыночную
переоценку, а не только новые решения.**

## Шаг 3. Прими решение по новому распределению
- Соотнеси тренды из истории радаров с текущим составом: что оправдалось, что нет.
- Проверь прошлые гипотезы из `docs/knowledge/portfolio_decisions_log.md`.
- Предложи распределение (только из допустимой вселенной, доли в сумме 100%),
  соответствующее коридорам инвестпрофиля. Выход за коридор допустим, но должен
  быть назван и обоснован явно.
- Не меняй состав радикально без сильного сигнала — обосновывай каждое значимое
  изменение причиной, а не констатацией.
- Если фиксированный watchlist пуст — выбирай инструменты сам и отдельно перечисли,
  какие тикеры имеет смысл добавить в `watchlist_config.json` для сопровождения.

## Шаг 4. Сгенерируй HTML-отчёт
Та же дизайн-система, что у радара (`templates/`), самодостаточный HTML без
внешних зависимостей:
- Титул: дата, тип пересмотра, стоимость портфеля и изменение с дня 0 (₽ и %)
- Таблица распределения по активам
- Диаграмма распределения по классам активов (инлайн SVG)
- График стоимости портфеля во времени по истории (инлайн SVG)
- Обоснование решений; что оправдалось из прошлых гипотез
- Соответствие инвестпрофилю: коридоры и текущее положение внутри них
- Дисклеймер: модельный портфель, не инвестрекомендация, не реальные сделки

Сохрани как `reports/portfolio/RU_Model_Portfolio_{YYYY-MM-DD}.html`.

## Шаг 5. Допиши историю
- Новая строка в `data/portfolio_history.jsonl` по схеме `data_schemas.md` §2
  (только дописывание).
- Новая запись в `docs/knowledge/portfolio_decisions_log.md` по шаблону:
  изменения с причинами, **проверяемые гипотезы этого пересмотра** и проверка
  прошлых гипотез.

## Шаг 6. Зафиксируй в git
Один коммит: отчёт + строка истории + запись журнала решений.
Сообщение: `portfolio: {YYYY-MM-DD} — {тип пересмотра}, {краткая причина}`. Затем push.

## Шаг 7. Доставь результат
- Прикрепи HTML-отчёт к результату задачи в Cowork.
- Письмо на **paladin_cool@inbox.ru**: тема `Модельный портфель — {дата}`,
  тело — 3–4 предложения об изменениях, вложение — HTML-файл.
- Если почтовый коннектор недоступен — явно сообщи об этом в результате.
