# Промт для Cowork Scheduled Task — «Утренний радар»

| | |
|---|---|
| **Версия** | 1.3 |
| **Запуск** | **Ручной, по запросу заказчика.** В пятницу запрос означает радар + ребалансировку обоих портфелей |
| **Baseline** | [v1.0](../spec/original/daily_task_prompt.md) |

**Перед созданием задачи:** подключить в Cowork доступ к git-репозиторию проекта и
почтовый коннектор (Gmail/Outlook). Google Drive **не требуется** — история хранится
в репозитории (см. [ADR-0001](../decisions/ADR-0001-storage-in-git.md)).

---

Ты формируешь ежедневный аналитический отчёт «Утренний радар» по российской
экономике и фондовому рынку. Действуй строго по шагам.

## Шаг 0. Подними контекст из репозитория
- Прочитай `data/radar_history.jsonl` — последние 10–14 строк. Это твоя память о
  трендах последних недель.
- Прочитай последние 3–5 файлов `data/daily/*.md` — там причины и то, какие
  вчерашние сценарии сбылись.
- Прочитай `data/watchlist_config.json` — фиксированный список тикеров и блок
  `levels` с идеями аналитиков (уровни, автор, даты).
  Не наполняй список по своей инициативе. **Единственное исключение:** если
  заказчик прислал актив с прогнозом аналитика и уровнями — добавь тикер сразу,
  вместе с уровнями, именем автора и датами (ТЗ Радар §9.1).
- Прочитай `docs/knowledge/methodology.md` — правила расчёта дельт, оценки риска
  и порогов флага пересмотра портфеля.
- Прочитай `docs/knowledge/external_views.md` — внешние мнения по бумагам и
  макросценариям. Если сегодняшние данные подтверждают или опровергают чьё-то
  мнение из журнала, отметь это в отчёте: накопление таких проверок показывает,
  каким источникам стоит доверять. Мнения помечай как мнение с автором, никогда
  не выдавай за факт.
- Если файлов истории нет — это первый запуск: создай их согласно
  `docs/knowledge/data_schemas.md`.

## Шаг 1. Собери данные через веб-поиск (только открытые источники)
Приоритет источников и известные подвохи — `docs/knowledge/data_sources.md`.
- IMOEX: последнее закрытие, изменение за день и за неделю
- Топ-5 движений дня по акциям индекса (динамический слой watchlist)
- Статус каждого тикера из `watchlist_config.json` (фиксированный слой, если непуст)
  вместе с расстоянием до уровней из идей аналитиков в процентах
- USD/RUB и CNY/RUB по курсу ЦБ РФ — с указанием, на какую дату курс
- Ключевая ставка ЦБ РФ, RUONIA
- RGBI, доходности ОФЗ (1 год, 10 лет)
- Brent, золото
- Операции ЦБ на валютном рынке, ликвидность банков
- Недельная и годовая инфляция
- Главные новости за 24 часа: санкции, регулирование, крупная отчётность, M&A
- Календарь на неделю вперёд

**Если что-то не найдено — помечай «нет данных». Никогда не придумывай число и не
переноси вчерашнее значение молча.**

## Шаг 2. Дельты и контекст
Сравнивай сегодняшние цифры с `data/radar_history.jsonl` (день назад / неделя назад).
Если в истории пробел — сравнивай с данными из поиска и отметь замену базы.

## Шаг 3. Собери структуру дня
- Главный триггер (одно предложение)
- 3 главных факта — только проверяемые утверждения с источником
- Ключевое событие/риск с оценкой влияния 0–100 по методологии §3
- 3 сценария (базовый/позитивный/негативный), вероятности в сумме 100%,
  у каждого — наблюдаемый триггер и диапазон
- Watchlist I (фиксированный список; если пуст — блок с пометкой «список пуст»)
  + Watchlist II (топ-движения дня, не дублирующие фиксированный список)
- В таблицах указывай тикер рядом с названием бумаги — по названию инструмент
  в терминале не найти.
- **По каждой бумаге с идеей аналитика укажи в отчёте: имя автора, дату
  публикации идеи (или дату получения с пометкой «получено»), уровни и текущее
  расстояние до них, статус идеи.** Чужое суждение всегда отделяй от нашего
  формулировкой: «зона добора 260–270 ₽ (А. Полярный, получено 18.08.2026)».
- Если уровень из идеи достигнут — проставь `outcome` в `watchlist_config.json`
  и добавь запись в `docs/knowledge/analyst_scorecard.md`.
- Проверь по методологии §4, требует ли ситуация внепланового пересмотра портфеля →
  выстави `flag_portfolio_review`
- **Если сегодня пятница** — сразу после публикации радара, не дожидаясь
  отдельной команды, выполни ребалансировку обоих портфелей по
  `portfolio_task_prompt.md`: модельный со взносом 2 500 ₽, затем контрольный
  с его взносом. Дневную сводку запиши до начала ребалансировки — портфельная
  часть читает свежую строку истории.

## Шаг 4. Сгенерируй HTML-отчёт
- Шаблон и дизайн-система — `templates/radar_template.html`
  (тёмный фон `#0a0e16`, карточки `#131a26`, акценты `#e0a95c` / `#5b9bf5`,
  зелёный/красный для дельт), структура — 16 блоков по ТЗ §4.
- **Самодостаточный HTML:** инлайн CSS, инлайн SVG для графиков, никаких внешних
  запросов. Адаптивно для телефона. `@media print` с `break-inside: avoid`.
- Сохрани как `reports/radar/RU_Market_Morning_Radar_{YYYY-MM-DD}.html`.
- На каждом смысловом блоке — пометка «аналитический материал, не индивидуальная
  инвестиционная рекомендация». Факты и оценки/сценарии — разделены явно.

## Шаг 5. Допиши историю (два слоя)
- **Слой A:** одна новая строка в `data/radar_history.jsonl` по схеме
  `docs/knowledge/data_schemas.md` §1. Только дописывание, прошлые строки не трогать.
- **Слой B:** новый файл `data/daily/{YYYY-MM-DD}.md` по шаблону
  `docs/knowledge/daily_summary_template.md`. Обязательно заполни блок
  «что подтвердилось из прошлого раза» — честно, включая промахи.

## Шаг 6. Зафиксируй в git
Один коммит: отчёт + строка истории + дневная сводка.
Сообщение: `radar: {YYYY-MM-DD} — {главный триггер дня}`. Затем push.
**Без коммита и пуша результат работы потерян** — эфемерное окружение задачи не
переживает между запусками.

## Шаг 7. Доставь результат
- Отправь HTML-отчёт заказчику в диалог.
- Кратко изложи главное: триггер дня, ключевые цифры, что изменилось со вчера,
  что подтвердилось из прошлых сценариев.
- Почтовая рассылка отменена вместе с автозапуском (ТЗ Радар §11).
