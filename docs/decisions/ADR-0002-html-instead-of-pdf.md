# ADR-0002. HTML вместо PDF как целевой формат отчётов

- **Статус:** принято
- **Дата:** 2026-08-18
- **Контекст ТЗ:** Радар §7.1, Портфель §8

## Контекст
В v1.0 целевым форматом обоих отчётов был PDF, рендер — через `weasyprint` из
HTML-шаблона. Заказчик попросил сменить формат на HTML.

## Решение
Целевой формат — **самодостаточный HTML-файл** (один файл, инлайн CSS, инлайн SVG,
без внешних запросов). PDF получается при необходимости через «Печать → PDF» и
не является обязательным выходом. Шаг рендера через `weasyprint` из пайплайна
удаляется.

## Почему это лучше для задачи
- **Один шаг вместо двух.** Шаблон и есть результат — исчезает целый класс сбоев
  на этапе рендера (шрифты, разбиение страниц, версия библиотеки).
- **Интерактив и графика.** Инлайн SVG, hover-подсказки, прокручиваемые таблицы —
  всё, что в PDF пришлось бы упрощать. Для 16-блочного дайджеста с графиками это
  существенно.
- **Чтение с телефона.** Утренний дайджест открывают в 7 утра с телефона; PDF на
  мобильном требует зума, адаптивный HTML — нет.
- **В теле письма.** HTML можно вставить прямо в письмо, а не только приложить.
- **Легче диффать.** Изменение шаблона видно в git-диффе построчно.

## Следствия и требования
- Файл обязан быть **автономным**: никаких CDN, внешних шрифтов как единственного
  варианта, картинок по ссылке. Иначе отчёт «сломается» офлайн или в почтовом клиенте.
- Нужен `@media print` с `break-inside: avoid` у карточек — чтобы «Печать → PDF»
  давала вменяемый результат, если PDF всё-таки понадобится.
- Тёмная тема — базовая и единственная, отчёт выглядит одинаково у всех.
- Некоторые почтовые клиенты режут `<style>` в теле письма — поэтому вложение
  HTML-файлом остаётся основным способом доставки, вставка в тело — дополнением.
- Ориентир по размеру файла — до 2 МБ.

## Рассмотренные альтернативы
- **Оставить PDF.** Отклонено заказчиком.
- **Выпускать оба формата.** Отклонено: удвоение поверхности сбоев ради формата,
  который получается печатью из HTML за два клика.
