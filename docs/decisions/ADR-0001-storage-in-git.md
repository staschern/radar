# ADR-0001. Хранение истории и знаний в git-репозитории

- **Статус:** принято
- **Дата:** 2026-08-18
- **Контекст ТЗ:** Радар §10, замена п.10 версии v1.0

## Контекст
В v1.0 предполагалось хранить историю (`radar_history.jsonl`, `portfolio_history.jsonl`,
`watchlist_config.json`, отчёты) на подключённом Google Drive — чтобы данные
переживали между запусками Cowork-задачи. Заказчик изменил требование: вся история,
все наработки, навыки, идеи и исследования должны храниться в документации на
GitHub и обновляться при каждом взаимодействии.

## Решение
Единственный источник правды — этот git-репозиторий. Google Drive не используется;
требование подключать соответствующий коннектор снято.

Раскладка:

| Что | Где |
|---|---|
| ТЗ и его версии | `docs/spec/` (+ неизменяемый baseline в `docs/spec/original/`) |
| Промты для Cowork-задач | `docs/prompts/` |
| База знаний, методология, идеи | `docs/knowledge/` |
| Архитектурные решения | `docs/decisions/` |
| История взаимодействий с заказчиком | `docs/sessions/` |
| Машинная история и конфиг | `data/` |
| Готовые отчёты | `reports/` |

## Почему так
- **Версионирование из коробки.** Видно не только текущее состояние, но и когда и
  почему оно изменилось — критично для ТЗ, которое будет постоянно дорабатываться.
- **Диффы как аудит.** Правка `watchlist_config.json` или пересмотр портфеля —
  это коммит с сообщением, а не бесследное изменение файла.
- **Append-only соблюдается механически.** Попытка переписать прошлую строку
  истории видна в диффе.
- **Знания и данные рядом.** Агент, готовя очередной радар, читает и историю, и
  методологию из одного места, одним и тем же способом.
- **Нет зависимости от внешнего коннектора** и его доступности на момент запуска.

## Следствия
- Каждый запуск задачи должен завершаться коммитом и пушем — иначе результат
  теряется вместе с эфемерным окружением. Это жёсткое требование к промтам задач.
- Репозиторий приватный: он содержит инвестиционный профиль заказчика и его почту.
- Нужна периодическая свёртка истории (архивы по годам), чтобы рабочие файлы
  оставались компактными для чтения агентом.
- Отчёты в `reports/` со временем распухнут; при необходимости перейдём на хранение
  только последних N отчётов + архив (пересмотреть при ~200 файлах).

## Рассмотренные альтернативы
- **Google Drive (v1.0).** Отклонено заказчиком. Плюс: удобно смотреть файлы.
  Минус: нет версионирования и внятной истории правок, зависимость от коннектора.
- **Cowork-сторедж.** Не переживает между запусками — исходно отвергнуто ещё в v1.0.
- **Внешняя БД.** Избыточно для объёма ~250 строк в год; усложняет чтение человеком.
