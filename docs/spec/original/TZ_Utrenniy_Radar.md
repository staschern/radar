# ТЗ: агент «Утренний радар»

## 1. Цель
Ежедневный (в будни) автоматический аналитический дайджест по российскому рынку в формате брендированного PDF, готовый к 07:00–09:00 мск, без участия пользователя.

## 2. Механизм запуска
**Claude Cowork → Scheduled Tasks.**
- Расписание: будни, время запуска — компенсировать 20–30 мин на сбор данных и рендер PDF (например, старт 06:30 мск, чтобы файл был готов к открытию рынка в 10:00 мск).
- Задача сохраняется один раз как промт-инструкция (см. `daily_task_prompt.md`) и запускается автоматически.
- Ограничение: данные ЦБ РФ и MOEX публикуются к определённому времени утра — нужно на старте проверить, что курс ЦБ на сегодня уже опубликован (обычно ~07:15–07:30 мск на завтра, публикуется накануне днём — уточнить фактическое время публикации перед финальной настройкой расписания).

| Блок | Источник |

## 4. Структура отчёта (на основе присланных примеров)
1. **Титул** — заголовок, дата, главный триггер дня, панель «рыночный пульс» (IMOEX / USD/RUB / ставка)
2. **Три главных факта дня** — короткие карточки с сутью
3. **Рыночная панель** — карточки метрик (IMOEX, USD/RUB, CNY/RUB, RGBI, Brent, золото) + бар-чарт движения акций + блок «контекст»
4. **Ключевое событие/риск дня** (санкции, ставка, крупная новость) — факт / что ещё не факт / рыночный механизм / чувствительные бумаги / оценка влияния 0–100
5. **Валюта/ликвидность** — покупки/продажи валюты ЦБ, структурный дефицит/профицит банков
6. **Инфляция и ставка** — недельный ИПЦ, годовая инфляция, RUONIA, интерпретация
7. **ОФЗ/кривая доходности** — RGBI, доходности 1г/10л, рыночный сигнал
8. **Корпоративные истории** — отчётность, M&A, дивиденды (2-3 карточки с фактом/сценарием/оценкой)
9. **Логика обратной связи** (диаграмма-цепочка: покупки валюты → рубль → инфляция → ОФЗ)
10. **Техническая карта индекса** — график, уровни поддержки/сопротивления, ширина рынка
11. **Watchlist I** — таблица блю-чипов (уровни, подтверждение/отмена, оценка)
12. **Watchlist II** — импульсные истории
13. **Календарь недели** — отчётность и события по дням
14. **Причинно-следственная схема** (аналог п.9, другой ракурс)
15. **Три сценария дня** — базовый/позитивный/негативный с вероятностями, триггерами, диапазонами
16. **Итоговый watchlist** — сводная таблица ключевых уровней + методология + главный риск

## 5. Правила расчёта дельт
- «За неделю» = сравнение с закрытием пятницы предыдущей недели (или последним доступным значением 7 дней назад).
- «За день» = сравнение с предыдущим торговым днём.
- Если данные по инструменту недоступны на момент генерации — блок помечается «нет данных», а не додумывается.
- Уровни поддержки/сопротивления и оценка влияния (0-100) — эвристика на основе волатильности/объёма/контекста, явно помечать как аналитическую оценку, не как факт.

## 6. Дизайн / визуальный стандарт
Уже воспроизведён и проверен (см. `radar_template.html` + прототип PDF):
- Тёмно-синий фон `#0a0e16`, карточки `#131a26` с рамкой `#232d3d` и скруглением 12–14px
- Акцентный золотой `#e0a95c` (заголовки блоков, ключевая ставка), синий `#5b9bf5` (валюта), зелёный/красный `#5bd88a` / `#e08a8a` (рост/падение)
- Шрифт: гротеск, жирные заголовки 30–44px
- Футер на каждой странице: методологическая пометка слева, номер страницы справа

## 7. Технический пайплайн генерации
1. Сбор данных → структурированный JSON (все метрики, дельты, тексты блоков)
2. Заполнение HTML-шаблона (Jinja-подобные плейсхолдеры)
3. Рендер в PDF через `weasyprint` (проверено, работает)
4. Сохранение файла с именем `RU_Market_Morning_Radar_YYYY-MM-DD.pdf`

## 8. Дисклеймеры и ограничения (обязательные, как в примерах)
- «Аналитический материал, не индивидуальная инвестиционная рекомендация» — на каждой странице
- Пометка о том, что уровни — зоны подтверждения, а не команды на сделку
- Явное разделение «факт» vs «сценарий/интерпретация»

## 9. Watchlist — гибридная логика
Каждый день агент формирует ДВА слоя watchlist:
1. **Фиксированный список** (задаётся и правится пользователем в файле `watchlist_config.json`, например `["SBER","GAZP","ROSN","LKOH","ALRS","AFLT","ASTR"]`) — по нему всегда есть блок с уровнями и статусом, даже если по бумаге ничего не произошло.
2. **Динамический слой** — агент дополнительно сканирует топ-5 движений дня по индексу (как в примерах: AFKS, VKCO, RUAL и т.п.) и добавляет их отдельной секцией, если они не входят в фиксированный список.
Если бумага одновременно и в фиксированном списке, и в топ-движениях — не дублировать, просто пометить как "движение дня".

## 10. Хранение истории — файловое окружение
Хранить не в памяти модели и не в одноразовом Cowork-сторедже, а в **подключённом облачном диске (Google Drive)** — так данные переживают между запусками задачи и видны пользователю напрямую.

Рекомендуемая структура папки `Утренний радар/`:
```
Утренний радар/
├── radar_history.jsonl        # по 1 строке JSON на день — сжатая сводка
├── portfolio_history.jsonl    # по 1 строке JSON на пересмотр портфеля
├── watchlist_config.json      # редактируемый фиксированный список тикеров
├── reports/
│   ├── RU_Market_Morning_Radar_2026-08-24.pdf
│   └── ...
└── portfolio/
    └── RU_Model_Portfolio_2026-08-24.pdf
```

Формат `radar_history.jsonl` (одна строка = один день, компактно, без лишнего текста):
```json
{"date":"2026-08-24","imoex":2168.4,"imoex_chg_d":1.5,"imoex_chg_w":-3.1,"usdrub":83.9,"cnyrub":12.44,"key_rate":14.0,"rgbi":114.6,"ofz10y":15.4,"brent":86.2,"gold":4350,"cpi_w":0.05,"cpi_y":6.0,"trigger":"Стабилизация после капитуляции: рынок ищет дно у 2100","risk_score":70,"flag_portfolio_review":false}
```
Именно этот файл — основа для аналитики «что происходило за последние N дней» при подготовке следующего радара и при пересмотре модельного портфеля.

**Требование к Cowork-задаче:** подключить Google Drive коннектор (см. `search_mcp_registry`/подключение через настройки Cowork) — без него история не переживёт между запусками задачи.
